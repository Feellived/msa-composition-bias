## ⭐ 1일차(08-05) 결과 — A·B·C 갈래는 여기서 접는다

세 가지 독립적인 방법(F1 단일선택 · binning 항체판별 · 상위3개 유의성)으로 같은 질문을
쳤고, 셋 다 같은 결론이었다 — **오라클(정답을 안 것)은 항상 유의하게 이기고, 실전
선택기는 전부 Bonferroni 보정 후 유의성에 못 미친다.**

```
A  binning 판별(RBD, 정제 후)   ncomp 실전 AUC 0.759 p=0.055(기준선 동률)
                                oracle 천장 AUC 1.000 p=0.017 ✅(기준선 초과)
                                abepi_max 실전 AUC 0.623 p=0.145 (ncomp보다도 못함)
C  상위3개 F1(정제 후)          기술적으론 천장 근접(iptm 0.548/0.549)이나
   상위3개 유의성 검정           무작위와 구별 안 됨(iptm p=0.090, Bonferroni 0.005)
B  단일선택 F1(정제 후)          ncomp_x_abemax 0.280→0.389(+0.109, p=0.041 보정전만)
   자체 성공기준(무작위도 같이 상승) 미달 — 무작위 0.326→0.302 로 오히려 하락
```

**결론: 정제(B)는 최고 선택기의 성능을 끌어올렸지만(ncomp_x_abemax +0.109) 평균은 못
올렸고, 어떤 선택기도 보정 후 유의하지 않다.** 선택 단계가 병목이라는 본문 핵심 주장이
완전히 다른 세 검증에서 독립적으로 재확인됐다 — 다만 "고치는 데 성공"은 아니다.

**판단**: 랩 데이터(binning·alanine scanning) 대조는 **보류한다** — 지금 어떤 선택기로도
유의한 판별이 안 되므로 랩 데이터가 와도 검증할 게 없다. 오라클 결과(binning AUC 1.000,
p=0.017)는 "정제된 후보 안에는 항체를 가를 정보가 실재한다"는 독립 증거로 발표에 남긴다.
발표 프레이밍 = §7의 "A 실패" 갈래("이 접근의 경계를 찾았다") + 세 검증이 일관됐다는
방법론적 강점.

**2일차부터는 E(비용 곡선)·F(사례 해부)로 넘어간다.** 선택기 사냥은 오늘로 종료.

### A. 같은 항원 × 다른 항체 — **최우선**

**묻는 것.** 지금까지 모든 시험이 복합체 하나당 항체 하나였다. 그래서 한 번도 확인하지
않은 게 있다 — **같은 항원에 다른 항체를 넣으면 우리 답이 달라지는가?**

안 달라진다면 우리는 항체–항원 결합을 예측하는 게 아니라 **항원 표면의 인기 있는 곳**을
찍고 있는 것이다. 그건 CLAUDE.md가 선택 단계에 쓰지 말라고 못박은 DiscoTope과 같은
물건이고, 파이프라인의 전제가 무너진다. **이 질문은 지금까지 아무도 우리에게 묻지 않았다.**

**공짜로 된다.** 이미 예측을 끝낸 30종 안에 같은 항원군 항체가 여럿 있다.

```
RBD  8종  8k3k_D 8k46_I 8k5g_HL 8k5h_HL 8kep_HL 8q7s_C 8q7s_H 8q7s_O   → 쌍 28개
HA   8종  8tp5_HL 8u44_ST 8ume_HL 9azr_HL 9azt_HL 9azv_HL 9b7g_QP 9bdg_FI → 쌍 28개
Env  3종  8t4a_PR 8t4d_OQ 8ulr_HL                                       → 쌍 3개
                                                                    합계 59쌍
```

특히 **8q7s_C · 8q7s_H · 8q7s_O 는 같은 PDB의 같은 항원**이다. 서열 정렬조차 필요 없는
가장 깨끗한 3쌍이다.

**어떻게 재나.** wet epitope binning과 같은 판으로 만든다.

- 정답 차단 행렬 = 결정 구조의 진짜 에피토프끼리 겹치면(자카드 ≥ 0.10) "차단"
- 예측 차단 행렬 = 우리가 고른 후보 자리끼리의 겹침
- **판별력(AUC)** = 예측 겹침이 정답 차단쌍을 위로 올리는가
- 순열검정 = 예측 자리를 항체에 무작위 재배정해도 이만큼 나오나

**기준선을 반드시 같이 본다.** 항체 서열 동일도만으로 다 맞혀지면 이 파이프라인은 필요 없다.
우리 차별점은 "서열이 달라도 같은 자리에 붙는 항체를 묶는다"이므로, **서열 기준선이 낮은데
우리가 높아야** 의미가 있다.

**표본이 커진다.** 23종에서 14승 9패로 p=0.40이던 검정력 문제를, GPU 없이 59쌍으로 바꾼다.

⚠️ 이 복합체들은 PDB에 있어 co-folder가 학습했을 수 있다. 우리는 항체 간 **상대 비교**를
하므로 절대 정확도만큼 치명적이진 않다. 발표에서 한 줄 언급한다.

### B. 후보 정제 정식 편입

`select_refine_sites.py`가 이미 다 구현돼 있다 — 손잡이 넷(`cons-frac`·`merge-frac`·`max-res`·
`main-patch`) sweep, 한-타깃-빼기(LOO) 정직 평가, `--dump-sites`로 정제된 후보 재생성까지.
**새로 짤 것이 없고 돌리기만 하면 된다.**

순서가 중요하다.

1. sweep → LOO로 **정답을 보지 않고** 설정을 고른다
2. 그 설정으로 `--dump-sites results/sites_refined`
3. `select_eval_selectors.py --sites results/sites_refined` 로 **정제 후 선택기 성능**을 잰다
4. `select_test_selectors.py` 로 정제 후에도 무작위와 구별 안 되는지 다시 검정

지금까지 잰 0.482→0.586은 **천장**이지 고를 수 있는 값이 아니다. 3단계가 진짜 답이다.

⚠️ `select_refine_sites.py`의 "현재 설정"이 `merge_frac=0`(합집합)으로 잡혀 있는데,
`analyze_site_reproducibility.py`의 기본값은 이미 `--merge-frac 0.75`(투표)다. **어느 쪽으로
sites_*.json이 만들어졌는지 먼저 확인**해야 비교 기준이 어긋나지 않는다.

### C. 상위 k개 산출 + 자세 수 편향 보정

**둘을 한 스크립트로 묶는다.** 둘 다 sites_*.json 재집계이고 서로 맞물린다.

**(1) 상위 k개.** 선택기 9개가 전부 무작위와 구별되지 않았다. 그러면 하나 고르기를 접고
**상위 2~3개를 다 내놓는 게** 실용적으로 낫다. 랩이 binning 실험을 설계할 때 "후보 자리 3개"는
충분히 쓸 만하다 — 변이체를 몇 개 만들지가 그걸로 정해지니까.

이건 실패를 감추는 게 아니라 **산출물의 형태를 바꿔 대응하는 것**이다.

**(2) 자세 수 편향.** `abepi_max`는 그 후보에 딸린 모든 자세 점수의 최댓값이다. 그런데
**자세가 많은 후보는 뽑기를 많이 했다는 이유만으로 최댓값이 커진다.** 그리고 실제로
조성이 많이 모인 후보를 고르는 `ncomp`는 0.284로 **무작위(0.326)보다 나쁘다.** 즉
"조성이 많이 모인 큰 후보"가 오히려 틀린 자리인데 `abepi_max`가 그쪽으로 끌려가고 있을 수 있다.

보정 두 가지를 새 선택기로 넣는다.
- `abepi_top3` — 상위 3개 자세 점수의 평균(개수에 덜 흔들림)
- `abepi_maxeq` — 후보마다 같은 수의 자세를 무작위로 뽑은 뒤 최댓값, 여러 번 평균

이게 유의해지면 **"선택기는 원래 신호가 있었는데 집계 방식이 망치고 있었다"**가 된다.
지금 결론과 정반대라 확인 가치가 크다.

⚠️ 이미 9개를 검정했다. 새 선택기는 **미리 둘만** 정해서 검정한다(§6에 박아둔다).

### D. 가짜 쌍 음성 대조 — 유일하게 GPU가 필요한 항목

지금까지는 **붙는다는 게 이미 확정된 쌍**만 넣었다. 랩 실무에서 정작 필요한 건
"이게 붙긴 붙나?"다.

**방법.** 항원은 그대로 두고 **다른 항원군의 항체**를 붙인다(RBD 항원 + HA 항체 등).
정의상 안 붙는 쌍이다. 우리 지표(모델 신뢰도·조성 간 합의)가 진짜 쌍과 가짜 쌍을 가르는가.

- **정답 구조가 필요 없다** — 가짜 쌍은 정의상 답이 없다
- **항원 MSA를 그대로 재사용한다** — `$DATA/ladders/<항원타깃>/`이 이미 있으므로 MSA 생성 불필요
- 갈린다면 **"Beacon 스크리닝 후보 중 진짜 결합체를 미리 거른다"**는 랩 용도가 생긴다

가짜 쌍 24개 × 조성 3개 × 반복 2회 정도로 시작한다. 진짜 쌍 쪽 값은 이미 다 있다.

### E. 조성 수 비용 곡선

조성을 몇 개까지 줄여도 결과가 유지되는지. **기존 조성의 부분집합으로 다시 집계만** 하므로
새 예측이 없다. 절반으로 줄여도 유지되면 랩에서 쓸 때 비용이 반이 된다.

발표에서 **"이건 랩에서 실제로 돌릴 수 있다"**를 뒷받침하는 유일한 정량 근거다.

## 5. 안전

- **모두 읽기 전용이거나 `results/` 밑에만 쓴다.** 기존 `sites_*.json`은 건드리지 않는다
  (정제본은 `results/sites_refined/`로 따로 나간다).
- **D만 새 폴더를 만든다** — `targets/decoy_*`. 기존 타깃 폴더는 안 건드린다.
- D의 예측은 GPU를 오래 쓴다. **돌리기 전에 반드시 허가를 받는다.**
- `$DATA`가 셸에 없으면 스크립트가 기본 경로로 넘어가되 경로를 화면에 찍는다. 찍힌 경로를 확인할 것.

## 6. ⭐ 판정 기준 — 결과를 보기 전에 박아둔다

여기 적힌 것만으로 판정한다. 나중에 문턱을 옮기지 않는다.

### A (같은 항원 다른 항체)

| 기준 | 값 |
|---|---|
| 정답 "차단" 판정 | 진짜 에피토프끼리 자카드 ≥ **0.10** |
| 주 지표 | 예측 겹침의 판별력 **AUC** |
| 성공 | AUC ≥ **0.65** 이고 순열검정 **p < 0.05** |
| 경계 | AUC 0.55~0.65 |
| 실패 | AUC < 0.55 — 우리 답은 항체와 무관하다 |
| 추가 조건 | **항체 서열 동일도 기준선의 AUC보다 높아야** 의미가 있다 |
| 항체 특이성 최소 조건 | 예측 자카드의 타깃 간 표준편차 > **0.05** (거의 상수면 항체를 안 보는 것) |
| 검정 | 순열 20000회 · 항원군을 합쳐 한 번, 군별로 각각 한 번 |

### B (후보 정제)

| 기준 | 값 |
|---|---|
| 설정 선택 | **LOO로만** 고른다. 30종 전체에서 최고를 고르지 않는다 |
| 후보 고갈 방어 | 평균 후보 수 ≥ **1.8** (기존 `select_refine_sites.py` 규칙 그대로) |
| 성공 | 정제 후 **선택기 평균 F1**이 정제 전보다 ≥ +0.03, 그리고 무작위 기준선도 함께 상승 |
| 주의 | 천장(F1 ceiling) 상승은 성공으로 치지 않는다. 고를 수 있어야 한다 |

### C (상위 k개 · 편향 보정)

| 기준 | 값 |
|---|---|
| 새로 검정할 선택기 | `abepi_top3` · `abepi_maxeq` **둘만** |
| 다중비교 | Bonferroni 0.05/2 = **0.025** |
| 성공 | 둘 중 하나가 순열 p < 0.025 |
| 상위 k 보고 | k=1,2,3 각각. 무작위 k개·천장과 나란히 |
| 실용 기준 | 상위 3개 안에 정답 절반 이상 덮는 후보가 있는 비율 ≥ **0.70** 이면 "실험 설계에 쓸 만하다"고 말한다 |

### D (가짜 쌍)

| 기준 | 값 |
|---|---|
| 주 지표 | 진짜 쌍 대 가짜 쌍의 판별력 **AUC** (모델 신뢰도 / 조성 간 합의 각각) |
| 성공 | AUC ≥ **0.70** |
| 표본 | 가짜 쌍 24개 이상 |

### E (비용 곡선)

| 기준 | 값 |
|---|---|
| 성공 | 조성 수를 절반으로 줄였을 때 F1 천장 하락 ≤ **0.03** |

## 7. 발표에서 어떻게 말할까

결과가 어느 쪽으로 나와도 할 말이 있게 미리 정해둔다.

- **A 성공** → 발표의 정점. "정답 구조 없이도 항체끼리를 가른다 → 랩 binning에 바로 쓴다"
- **A 실패** → 정직한 음성 결과. "이 파이프라인의 답은 항체가 아니라 항원이 정한다"는
  **경계를 찾은 것**이고, 이건 아무도 우리에게 묻지 않았던 질문이다. 발표에서 감추지 않는다.
- **B 성공** → "선택기를 못 고쳐도 성능은 오른다 — 병목을 우회했다"
- **C** → "고르기가 안 되면 안 골라도 되는 산출물을 낸다"는 설계 변경
- **D 성공** → 랩이 바로 쓸 용도가 하나 더 생긴다
- **E** → "랩에서 실제로 돌릴 수 있다"

## 8. 랩 데이터 요청 (별도 트랙, 리드타임 있음)

alanine scanning 쪽을 우선한다 — 잔기 단위라 우리 출력과 바로 맞물리고, 평가가 AUC로
되어 **후보 크기 문제가 평가에서 아예 빠진다.**

⭐ **서열만 먼저 받고 실험 결과는 예측을 고정한 뒤에 받는다.** 예측을 커밋해 시각을 박아두면
"결과를 보고 맞춘 게 아니다"를 증명할 수 있다. 이 프로젝트의 가장 큰 약점을 정면으로 해결한다.

받을 것 — 항원 구조체 서열 / **잔기 번호 체계** / 발현 시스템 / 항체 VH·VL 서열,
그리고 나중에 원본 차단 행렬(또는 시험한 잔기 **전체** 목록, 안 떨어진 것 포함).
